CLOUDFLARE WORKERS · OFFICEJUR

Configure o Cloudflare Worker compartilhado do OfficeJur

Este guia mostra como publicar o Worker protegido, cadastrar seus segredos e conectar as integrações atuais do OfficeJur — Mercado Pago, DataJud e futuras APIs — em uma configuração global.

Credenciais privadas nunca vão para o navegador

Access Tokens, chaves do DataJud e a chave de acesso do serviço devem existir somente como segredos protegidos na Cloudflare ou na sessão local do navegador, conforme a finalidade. Nunca os coloque no código, no GitHub, no Gist ou em capturas de tela.

VISÃO GERAL

Por que existe um serviço separado?

As páginas do OfficeJur são estáticas e não possuem um servidor privado para guardar credenciais. Por isso, o navegador envia somente dados autorizados ao Worker compartilhado. O Worker valida a origem e a chave do serviço, aplica limites e conversa com cada API usando os segredos corretos.

OfficeJurSolicita a integração
Cloudflare WorkerAutoriza e roteia
APIs externasMercado Pago, DataJud e outras
  • A chave do serviço autoriza o navegador sem expor os segredos das integrações.
  • Cada rota usa somente os dados e segredos necessários para sua finalidade.
  • O mesmo Worker pode receber novas integrações sem criar uma configuração por módulo.
  • As APIs externas continuam responsáveis por suas próprias credenciais, limites e estados.

O que será necessário

Conta Cloudflare

Uma conta com acesso a Workers para publicar e proteger o serviço.

O código versionado em apps/financeiro/worker e o arquivo de configuração Wrangler.

Segredos por integração

Cadastre somente os segredos das APIs que serão utilizadas: Mercado Pago, DataJud e outras futuras.

Endereço do sistema

A origem HTTPS do OfficeJur para configurar o acesso permitido.

ETAPA 1

Crie e publique o Worker compartilhado

O repositório já contém o código necessário. A configuração pode ser feita inteiramente pelo painel da Cloudflare, sem instalar programas no computador. O nome sugerido é financeiro-officejur porque o serviço não pertence a um único módulo.

  1. 1
    Abra o painel da Cloudflare

    Entre na conta do escritório e acesse Workers & Pages.

    Abrir Cloudflare Dashboard
  2. 2
    Crie um Worker

    Escolha criar um Worker, use o nome financeiro-officejur e publique o exemplo inicial.

  3. 3
    Abra o editor de código

    No Worker recém-criado, escolha Edit code ou Quick edit e apague o exemplo.

  4. 4
    Publique o Worker revisado

    Abra o código versionado do serviço, revise as rotas e publique-o pela Cloudflare. O mesmo Worker intermedeia o Mercado Pago, a consulta pública do DataJud e futuras integrações.

    Abrir código do Worker
  5. 5
    Salve e publique

    Escolha Save and deploy. Guarde o endereço final, semelhante a https://financeiro-officejur.sua-conta.workers.dev.

A chave de acesso é criada pelo escritório

A OFFICEJUR_API_KEY não é fornecida por nenhuma API externa. Gere uma chave aleatória longa, guarde-a em um gerenciador de senhas e use o mesmo valor no segredo do Worker e na configuração global de Cloudflare Workers do OfficeJur.

Alternativa para desenvolvedores: publicar pelo terminal

Dentro da pasta worker, use Wrangler 4.36.0 ou superior, autentique a conta, ajuste ALLOWED_ORIGINS e confirme o identificador exclusivo do limitador em wrangler.toml. Depois, publique o código com npx wrangler deploy e cadastre os segredos com npx wrangler secret put MP_ACCESS_TOKEN, npx wrangler secret put DATAJUD_API_KEY e npx wrangler secret put OFFICEJUR_API_KEY. O comando secret put publica a alteração imediatamente quando a versão mais recente já está publicada.

ETAPA 2

Cadastre as variáveis e os segredos

No Worker, abra Settings → Variables and Secrets. Adicione os itens abaixo e publique a nova versão quando a Cloudflare solicitar.

ALLOWED_ORIGINS — texto normalInforme somente a origem do sistema, sem caminho e sem barra final. Exemplo: https://seu-dominio.example. Para várias origens, separe por vírgula.
OFFICEJUR_API_KEY — tipo SecretCrie uma chave aleatória, como com openssl rand -hex 32. Cole-a neste segredo e depois informe exatamente o mesmo valor em Configurações → Cloudflare Workers.
MP_ACCESS_TOKEN — tipo SecretCole o Access Token do ambiente que será usado. Selecione explicitamente o tipo segredo para que o valor fique oculto no painel.
DATAJUD_API_KEY — tipo SecretCadastre a credencial vigente do CNJ para que o Worker faça a consulta sem depender de CORS no navegador.
MP_WEBHOOK_URL — opcionalReservado para notificações automáticas. Não é necessário para criar links nem para consultar pagamentos pelo botão de atualização.
Como gerar e cadastrar a OFFICEJUR_API_KEY?
  1. 1
    Gere a chave

    No macOS ou Linux, execute openssl rand -hex 32 e guarde o resultado. Também é possível usar o gerador do seu gerenciador de senhas.

  2. 2
    Cadastre o segredo

    No painel da Cloudflare, adicione OFFICEJUR_API_KEY como Secret. Pelo terminal, dentro da pasta worker, execute npx wrangler secret put OFFICEJUR_API_KEY e cole a chave quando solicitado.

  3. 3
    Repita a chave no OfficeJur

    Na área central Configurações → Cloudflare Workers, informe o mesmo valor. A chave fica salva neste navegador, mas não deve ser salva no código, no Git ou no Gist.

Se o Wrangler informar que a versão mais recente ainda não está publicada, primeiro execute npx wrangler deploy e repita o cadastro. Como alternativa, use npx wrangler versions secret put OFFICEJUR_API_KEY e depois npx wrangler versions deploy para publicar essa versão.

Origem não é o endereço completo

Use apenas https://seu-dominio.example em ALLOWED_ORIGINS, sem o caminho da aplicação.

Teste a saúde do serviço

Abra o endereço do Worker acrescentando /health. Com a origem e a chave de acesso configuradas corretamente, a resposta será {"ok":true}. Os segredos específicos são verificados somente quando a respectiva rota é utilizada.

Documentação da Cloudflare

Segredos são apropriados para chaves e tokens porque o valor deixa de ser exibido no painel depois de cadastrado.

ETAPA 3

Configure o OfficeJur globalmente

  1. 1
    Abra Configurações

    Use o menu do OfficeJur e abra a área central Configurações.

  2. 2
    Informe a URL e a chave do Worker

    Na seção Cloudflare Workers, cole o endereço sem /health e informe a mesma OFFICEJUR_API_KEY cadastrada na Cloudflare.

  3. 3
    Salve a configuração global

    A URL e a chave serão usadas pelos módulos que precisarem do Worker e permanecerão salvas neste navegador. Elas não são sincronizadas pelo Gist.

  4. 4
    Configure cada integração

    Mercado Pago usa o Access Token cadastrado no Worker. DataJud usa o Worker automaticamente ao informar um CNJ judicial.

  5. 5
    Teste a saúde do serviço

    Abra a URL do Worker com /health e confirme a resposta antes de testar as integrações.

INTEGRAÇÃO ATUAL

DataJud

O cadastro de casos judiciais consulta o DataJud pelo Worker para contornar a ausência de CORS na API pública. Quando a configuração global estiver completa, o OfficeJur envia o CNJ ao Worker e recebe os dados públicos disponíveis, incluindo movimentações quando fornecidas.

Segredos diferentes

DATAJUD_API_KEY autoriza o Worker perante o CNJ. OFFICEJUR_API_KEY autoriza o navegador perante o Worker. Não são a mesma chave.

Sem URL e chave globais do Worker, o CNJ continua obrigatório, mas os campos do caso judicial ficam disponíveis para preenchimento manual. Com o Worker configurado, uma falha de consulta mantém o cadastro bloqueado para evitar dados incompletos.

ETAPA 5

Gere e valide a primeira cobrança

  1. 1
    Prepare um lançamento

    Cadastre um cliente com nome e e-mail. Crie uma receita vinculada ao cliente e mantenha o status como pendente.

  2. 2
    Crie o link de pagamento

    Em Cobranças, escolha “Gerar cobrança”, selecione o lançamento e confira valor, vencimento, descrição e pagador.

  3. 3
    Use um comprador de teste

    No Mercado Pago Developers, abra Contas de teste → Comprador. Faça o teste em uma janela anônima e nunca use um cartão real com credenciais de teste.

    Consultar teste de integração
  4. 4
    Simule o resultado

    Conclua a compra com os dados de teste indicados pelo Mercado Pago.

  5. 5
    Atualize o status

    Volte à tabela de cobranças e use o ícone de atualização. Quando o pagamento estiver aprovado, o lançamento será marcado como realizado e receberá a forma “Mercado Pago”.

ETAPA 6

Ative pagamentos reais

Só avance depois de concluir os testes

Teste criação do link, retorno ao sistema e atualização de pagamento. Credenciais de teste e produção não podem ser misturadas.

  1. 1
    Ative as credenciais de produção

    Na aplicação do Mercado Pago, abra Produção → Credenciais de produção, complete os dados solicitados e ative as credenciais.

  2. 2
    Troque o segredo na Cloudflare

    Substitua MP_ACCESS_TOKEN pelo Access Token de produção e publique a alteração.

  3. 3
    Faça uma validação controlada

    Gere uma cobrança real de pequeno valor, confirme o recebimento e valide o lançamento antes de disponibilizar o fluxo aos clientes.

HTTPS obrigatório

O endereço de produção do sistema e o Worker devem utilizar HTTPS. O GitHub Pages e o domínio workers.dev já fornecem conexão segura.

SOLUÇÃO DE PROBLEMAS

Mensagens e correções mais comuns

“Failed to fetch” ou erro de CORS
Confira a URL do Worker e a variável ALLOWED_ORIGINS. Informe apenas a origem do sistema, sem o caminho /financeiro e sem barra no final. Depois, publique novamente o Worker.
“MP_ACCESS_TOKEN não configurado”
O segredo precisa se chamar exatamente MP_ACCESS_TOKEN, estar no mesmo Worker e no ambiente publicado. Confirme que o tipo escolhido foi Secret e que a implantação foi concluída.
Erro 401 ou “Serviço não autorizado”
Confira se OFFICEJUR_API_KEY existe como Secret no Worker e se a chave informada em Configurações → Cloudflare Workers é exatamente igual. Se a chave tiver sido exposta, gere outra, substitua o segredo no Worker e atualize a configuração global do OfficeJur.
“A versão mais recente do Worker ainda não está publicada”
Esse aviso aparece quando o Wrangler está usando versões separadas de código e implantação. Publique primeiro com npx wrangler deploy e depois repita npx wrangler secret put NOME_DO_SEGREDO. Se quiser manter o fluxo separado, use npx wrangler versions secret put NOME_DO_SEGREDO e finalize com npx wrangler versions deploy.
“O proxy DataJud ainda não foi configurado”
Cadastre também DATAJUD_API_KEY como Secret no Worker. Ela é diferente da OFFICEJUR_API_KEY: a primeira autoriza o Worker perante o CNJ; a segunda autoriza o navegador perante o Worker.
Erro do Access Token do Mercado Pago
O Access Token pode estar incorreto, revogado ou ser de outra aplicação. Troque o segredo na Cloudflare e confirme que a credencial escolhida corresponde ao ambiente que deseja usar.
O link continua abrindo o ambiente de testes
Na Cloudflare, confirme que MP_ACCESS_TOKEN contém o token produtivo e publique a alteração. O ambiente do checkout é definido pela credencial usada no Worker.
A cobrança foi paga, mas continua pendente
Use o botão de atualizar status. Confirme que o pagamento foi realizado no mesmo ambiente da cobrança e que a referência externa existe no Mercado Pago. A confirmação atual é consultada pelo sistema; o webhook é opcional.
O retorno após o pagamento está incorreto
Revise a “URL de retorno” no Financeiro. Ela deve conter o endereço HTTPS completo do sistema, incluindo o caminho do projeto quando existir.
Como atualizar o Worker no futuro?
Abra worker/src/index.js neste repositório, copie o conteúdo atualizado, substitua o código no editor da Cloudflare e escolha “Save and deploy”. Variáveis e segredos normalmente permanecem cadastrados.

Regras de segurança

  • Nunca coloque o Access Token no código, Gist ou configuração visível do navegador.
  • Restrinja o acesso às contas do Mercado Pago e da Cloudflare e ative autenticação em dois fatores.
  • Revogue e substitua imediatamente qualquer credencial que tenha sido exposta.
  • Valide mudanças em ambiente de testes antes de alterar a integração produtiva.

Ao pedir suporte, informe a mensagem apresentada, a etapa do guia e o endereço público do Worker. Nunca envie o Access Token nem imagens que mostrem credenciais.
